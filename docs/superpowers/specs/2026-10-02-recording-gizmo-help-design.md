# Bodycam Diagnostics: управление записью, совместимость с Gizmo и русская справка

Дата: 2026-10-02

## Исходные данные

Реальные прогоны сборки `stable-c238eb1` подтвердили:

- PresentMon, FFmpeg, NVENC, WASAPI и телеметрия запускаются на клубном ПК
- один прогон прошёл как `VALID`
- три прогона были испорчены разрывами PresentMon или видео
- во время испорченных прогонов одновременно наблюдались iSCSI, NDIS, DNS и disk 153 события
- FFmpeg получил `AcquireNextFrame failed: 0x887A0026` после потери Desktop Duplication
- старая Gizmo закрывает диагностическую цепочку по эвристике доступа к системным данным
- в отдельных отчётах разрыв PresentMon ошибочно выглядит как очень длинный игровой фриз

## Цели

1. Пользователь независимо управляет диагностикой и записью видео
2. Отказ записи не останавливает сбор FPS и телеметрии
3. Разрыв источника данных не классифицируется как игровой фриз
4. Программа объясняет состояние и результаты на русском языке
5. Есть режим с уменьшенным числом системных запросов для старой Gizmo
6. Выпуск остаётся переносимым; отдельно исследуется вариант одного EXE

## Интерфейс

Главное окно получает отдельные элементы:

- `Начать тест` / `Остановить тест`
- `Начать запись видео` / `Остановить запись видео`
- индикатор `Видео: выключено / запись / ошибка`
- флажок `Режим совместимости с Gizmo`
- кнопку `Справка`

Запись по умолчанию выключена. Диагностический тест можно запустить без FFmpeg. Горячие клавиши:

- F9 — начать или остановить тест
- F8 — начать или остановить видео во время активного теста
- F10 не назначается повторно, пока поведение старых сборок не будет мигрировано явно

## Состояния записи

RecorderController работает независимо от состояния теста:

- `Disabled` — запись не запрошена
- `Starting` — проверка FFmpeg и запуск
- `Recording` — кадры поступают
- `Lost` — захват потерян
- `Stopped` — запись штатно завершена

При `0x887A0026` программа сообщает: `Захват экрана потерян: графическая или удалённая сессия была сброшена`. Автоматический бесконечный перезапуск запрещён. Один контролируемый перезапуск допускается только при стабильной диагностической сессии.

В `session.json` и итоговом отчёте сохраняются интервалы фактической записи. Валидация сравнивает видео только с периодом, когда запись была включена.

## Разрывы PresentMon

Последовательность кадров разделяется на непрерывные интервалы. Интервал закрывается при одном из условий:

- временная метка идёт назад
- пауза значительно превышает ожидаемый кадр и рядом меняется режим представления
- источник прекращает выдавать события и затем возобновляется
- процесс игры или графическая сессия меняет состояние

Пауза между интервалами сохраняется как `CAPTURE_GAP`. Она не входит в максимальный frametime, 1% low, 0,1% low и число игровых фризов.

`summary.json` и `session_diagnostics.json` используют одну нормализованную последовательность кадров, поэтому максимальный frametime и счётчики совпадают.

## Режим совместимости с Gizmo

Режим уменьшает активность, на которую реагирует старая Gizmo:

- не читает Windows Event Log
- не собирает логи Bodycam
- не запускает полноэкранный helper
- не включает видео автоматически
- сохраняет PresentMon и базовую телеметрию, поскольку это основная функция программы
- явно перечисляет отключённые источники в отчёте

Режим не маскирует процессы, не обходит защиту и не изменяет файлы Gizmo.

## Русская справка

В поставку входит `СПРАВКА.txt` в UTF-8. Кнопка `Справка` открывает его. Документ объясняет:

- назначение программы
- назначение каждой кнопки и горячей клавиши
- какие данные программа читает
- какие файлы создаёт
- статусы `VALID`, `INVALID`, `CLEAN`, `CONTAMINATED`
- действия при потере видео, сети, iSCSI или закрытии Gizmo
- ограничения диагностики и конфиденциальность отчёта

Ключевые ошибки интерфейса также переводятся на русский. Технические имена файлов и компонентов сохраняются без перевода.

## Упаковка

Основной выпуск остаётся переносимой папкой с проверяемыми SHA-256 зависимостями. Это сохраняет прозрачность и позволяет Gizmo/администратору видеть каждый компонент.

Экспериментальный `Single EXE` допускается отдельным артефактом. Он распаковывает подписанные или хешированные PresentMon и FFmpeg в каталог пользователя, проверяет SHA-256 и удаляет временные копии после штатного завершения. Этот вариант тестируется отдельно, потому что само извлечение исполняемых файлов может вызвать эвристику старой Gizmo.

## Проверки

Разработка ведётся через тесты:

1. запись можно включить и выключить внутри активной сессии
2. тест без видео формирует диагностический отчёт
3. длительность видео проверяется только по интервалам записи
4. `0x887A0026` даёт понятный статус потери захвата
5. разрыв PresentMon создаёт `CAPTURE_GAP` и не увеличивает frametime
6. значения max frametime и счётчиков совпадают в обоих отчётах
7. режим Gizmo не запускает отключённые сборщики
8. русская справка входит в runtime package

## Критерии готовности

- Windows CI проходит полностью
- новый отчёт различает игровой фриз и потерю источника
- пользователь может провести тест без видео, затем включить запись отдельной кнопкой
- интерфейс и справка понятны без чтения исходного кода
- обычная portable сборка остаётся основным проверяемым выпуском
